# @linky-fit/expo

Builds `apps/linky-app` for the web with Expo/Metro and expo-router, and builds the iOS and Android apps from the same code: `src/main.native.ts` installs the polyfills and boots the web app's session on the native ports (`apps/linky-app/src/platform/nativePorts.native.ts`). This package holds bundler and native-project glue only; app code, `index.html`, `public/` files and the PWA manifest (`server/webManifest.ts`) live in `apps/linky-app`, and `scripts/preparePublic.ts` regenerates `public/` from them.

- Metro resolves `apps/linky-app/src/platform/buildEnv.ts` to `src/buildEnv` and `platform/navigation.ts` to `src/navigation`, whose `.native` siblings win on iOS and Android. A change to either seam goes into every variant; the `*.contract.ts` files fail the typecheck until they match.
- expo-router owns navigation: the seam navigates with `router.push`/`router.replace`, and `useCurrentRoutePath` reads the router's pathname and search params. `app/_layout.tsx` renders the app shell once around `<Slot />`; the route files render nothing, as the shell picks the page from the route. A navigation must never remount the shell, which `appshell-parity.spec.ts` asserts through back and forward.
- Back and forward reach expo-router only as a `router.replace` from the seam's popstate listener: given the raw event, it rebuilds its whole tree from history it did not record, which remounts the shell.
- A route segment's `%` is written as `~` in the URL (`~~` for a literal `~`), so router decoding never turns an encoded `/` in a mint or relay URL into a separator (`src/routeUrl.ts`).
- On iOS and Android every navigation is a `router.replace`: back (Android button, iOS edge swipe) walks up the route hierarchy through `resolveNativeBackAction`, and a router history would let expo-router's own back handler pop it instead. Links the OS opens the app with reach `redirectSystemPath` (`app/+native-intent.tsx`), which hands them to `hashLinks.native.ts` once; their pending storage is the web's.
- `currentRoutePath()` reads the address bar, which follows a router navigation after its render. Code that reloads into a route uses `reloadAtRoutePath`.
- Payment details and command-link payloads stay out of URL paths and queries. A bank payment URL carries an `spd-<id>` whose SPAYD waits in sessionStorage (`src/routeUrl.ts`); fragments such as `#add/…` or `#linkauth…` stay fragments for their handlers.
- Every server of the export answers a path outside `/_expo/`, `/assets/` and the static directories with `index.html`: `docker/linky-app/nginx.conf`, `scripts/serve.ts` and the service worker's navigation route do.
- Production serves the service worker at `/sw.js`, scope `/`, as a classic script, the same as the Vite build. Installed apps treat a changed URL or type as an update.
- The Expo dev server runs without a service worker.
- Production builds tree-shake, which drops Metro's worker bundles. A web worker the app starts gets a Bun bundle in `scripts/build.ts`, as `evoluDb.worker.ts` has.
- `scripts/bundleSize.ts` holds the gzip budget for the exported JS. Raise it in the same change that adds the bytes.

## Native (iOS and Android)

- Metro picks a `foo.native.ts(x)` sibling over `foo.ts(x)` on iOS and Android; Vite never sees it. Metro tries each extension in turn, `.ts` before `.tsx`, so a sibling takes its base's extension (`src/main.native.ts` stays `.ts`).
- Every `.native` module of `apps/linky-app/src`, `src/` and `packages/ui/src` exports what its web sibling exports: `src/native.contract.ts` pairs them (`tsconfig.contract.json`), and `nativeContract.test.ts` fails on a missing linky-app or expo pair. `tsconfig.native.json` resolves `.native` first, so a sibling that imports `./foo` gets itself; shared types go in a third module.
- In `packages/ui` the plain file is the native implementation. A component that needs a native module ui does not declare lives in a `.native.tsx` sibling, which ui's own tsconfig skips and `tsconfig.native.json` checks.
- Native modules are declared only in this package (`bunx expo install <pkg>` here; declaring them in `apps/linky-app` too runs Linux's frozen `bun install` out of memory). Metro resolves linky-app's and ui's imports of them from here; give each a `paths` entry in `tsconfig.native.json` and `tsconfig.contract.json`.
- `ios/` and `android/` are generated by `bun run native:prebuild` and not committed; native changes go into `app.config.ts`, a config plugin in `plugins/` or a local Expo module in `modules/`. iOS 27 needs the scene lifecycle `plugins/withSceneLifecycle.ts` adds.
- `LINKY_APP_VARIANT` picks the app id (`app.config.ts`). Local builds use the default `dev` variant, `fit.linky.expo.dev` on both platforms, so they never install over a Capacitor app.
- `plugins/withLinkySigning.ts` signs Android debug builds with `LINKY_ANDROID_DEBUG_KEYSTORE` (default `~/.android/debug.keystore`, the Capacitor app's, so an update installs in place) and release builds with the `LINKY_UPLOAD_*` key; iOS signs with team `LINKY_IOS_TEAM`.
- Build: `bun run native:prebuild`, then `./gradlew :app:assembleDebug` in `android/` (with `ANDROID_HOME` set) or `xcodebuild -workspace ios/LinkyExpoDev.xcworkspace -scheme LinkyExpoDev`; `bun run expo:android` / `expo:ios` build and install on a connected device in one step. Run the bundle with `bun run start:native -- --port <port>` and open `exp+linky://expo-development-client/?url=http%3A%2F%2Flocalhost%3A<port>` on the device.
- Metro remembers how it resolved an import: after adding a `.native` sibling to a module that is already imported, restart it.
- Android dev builds reach Metro and the local stack through `scripts/adbReverse.ts` (honours `ANDROID_SERIAL`; reverse a non-default Metro port yourself). `LINKY_DEV_HOST=<LAN IP>` points the `.env.development` service URLs at this machine for a device that cannot reach its localhost (an iPhone). The web app's Vite dev server takes the same variable, so a web peer publishes relay lists and tokens the device can reach.
- Dev builds post inspector rows to the Metro server that served the bundle (`inspectorCollectorOrigin` in `src/buildEnv.native.ts`), so `GET /__inspector/events` on the Metro port shows them; release builds keep them on the device.
- `/api/*` goes to `https://app.linky.fit` unless `EXPO_PUBLIC_API_ORIGIN` names another origin. Metro serves `/api/link-preview` and `/api/lnurlp` itself (`server/devMiddleware.ts`), so `EXPO_PUBLIC_API_ORIGIN=http://localhost:<Metro port>` tests them locally.
- Identity secrets live only in expo-secure-store. A write it refuses restores the previous values and shows the couldn't-store screen (`SecretsWriteFailed`), never a plaintext copy.
- A reload restarts the JavaScript app through `reloadAppAsync`, keeping sessionStorage and the route as a page reload does (`platform/restartApp.native.ts`).
